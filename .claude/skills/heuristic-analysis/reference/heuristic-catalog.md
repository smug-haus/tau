# Heuristic Catalog

Reference for all implemented heuristics. Each entry covers: detection logic, confidence levels, and kill reason template.

---

## H-001 — Edit-undo cycle

**Description**: A file returns to a previously observed content hash within a short window of steps.

**Detection logic**:
- Maintain a rolling hash history of the last N writes per file path
- On each Edit/Write, compute SHA-256 of new content
- If the hash matches a previous state seen within the last 5 steps → trigger
- Excludes files explicitly marked as test fixtures

**Confidence levels**:
- `0.7` — first occurrence (could be intentional revert)
- `0.95` — second occurrence on the same file within the session

**Kill reason template**:
```
H-001: Edit-undo cycle detected on {file_path}. File returned to hash {short_hash} (seen {n} steps ago). Agent appears to be oscillating.
```

## H-003 — Repeated identical calls

**Detection logic**:
- Hash each tool call as `{tool_name}:{sorted_args_json}`
- Maintain a sliding window of the last 10 tool calls
- If the same hash appears 3+ times in the window → trigger
- Excludes read-only tools: Read, Glob, Grep, Bash with read-only commands

**Confidence levels**:
- `0.85` — 3+ repetitions in window

**Kill reason template**:
```
H-003: Repeated identical call detected. Tool {tool_name} called with identical arguments {n} times in last {window} steps. Agent appears stuck.
```

## H-004 — Test failure plateau

**Detection logic**:
- Parse test runner output after each Bash call that invokes a test suite
- Extract: total tests, passing, failing counts
- Maintain a rolling buffer of the last 3 runs
- Plateau: failure count unchanged across all 3 runs → trigger
- Worsening: failure count increased in most recent run → trigger

**Confidence levels**:
- `0.7` — plateau (same failure count, no improvement)
- `0.9` — worsening (failure count increased)

**Kill reason template**:
```
H-004: Test failure plateau. Failure count: {counts_series}. No improvement across {n} consecutive runs. Current approach is not converging.
```

## H-005 — Context burn

**Detection logic**:
- Count cumulative tool calls since last Edit, Write, or test improvement
- If count exceeds 50 with no qualifying action → trigger
- Resets on any Edit/Write or test run showing improvement

**Confidence levels**:
- Capped at `0.6` regardless of call count — this heuristic has higher false-positive rate

**Kill reason template**:
```
H-005: Context burn. {n} consecutive tool calls with no writes or test improvement. Agent appears to be reading without acting.
```

## H-008 — Error echo

**Detection logic**:
- Capture stderr text from all Bash calls (minimum 20 chars to exclude noise)
- On subsequent Edit or Write calls, check whether any captured stderr substring (≥20 chars) appears verbatim in the written content
- Normalize whitespace before comparison

**Confidence levels**:
- `0.7` — verbatim match found

**Kill reason template**:
```
H-008: Error echo detected. Stderr content from step {n} appears verbatim in {file_path} at step {m}. Agent is echoing errors rather than fixing them.
```

## D-xxx — Design constraint violations

**Description**: Project-specific structural rules generated by the PSDH emitter and loaded at session start.

**Detection logic**: Varies per constraint. Each D-xxx heuristic is a self-contained check defined in the PSDH catalog. All D-xxx heuristics implement the same interface as H-xxx heuristics: they receive the current tool call context and return a JSON result with `confidence`, `kill_reason`, and `escalation_level`.

**Confidence levels**: Defined per-constraint in the PSDH catalog.

**Kill reason template**: Defined per-constraint in the PSDH catalog.

## Escalation Ladder

| Confidence | Action |
|---|---|
| 0.4 – 0.6 | `additionalContext` — soft nudge injected into next tool response |
| 0.6 – 0.8 | `decision: block` — forced acknowledgment before proceeding |
| 0.8 – 0.9 | Kill signal + `decision: block` |
| ≥ 0.9 | Kill signal + `exit 2` (hard block, session cannot continue) |
| Combined: 2+ heuristics at ≥ 0.6 | Kill signal (regardless of individual levels) |

**Kill signal mechanics**: A kill signal writes a sentinel file to the worktree's `.claude/logs/kill/` directory containing the heuristic ID, confidence, and kill reason. The coordinator reads this file after the subagent terminates to populate the solution tree.
